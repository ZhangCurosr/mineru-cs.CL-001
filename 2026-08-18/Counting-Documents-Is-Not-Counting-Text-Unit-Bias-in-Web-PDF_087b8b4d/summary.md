# 论文速读：Counting-Documents-Is-Not-Counting-Text-Unit-Bias-in-Web-PDF

## 一句话总结
本文揭示当前Web-PDF语料库存在严重的“单位偏差”：虽以token数宣传规模，但覆盖率、路由、截断损失等关键指标均按文档数计算且从不分解token总量。研究证明token分布高度集中，Common Crawl的字节截断阈值实际摧毁了55%–62%的语料文本，并呼吁语料库统计必须同时报告文档数与token数。

## 研究问题与动机
1. **核心问题**：PDF语料库在汇报指标时计量单位不一致（token总量 vs. 文档级比率），导致对语料构成、质量分布与清洗策略的评估产生系统性偏差。
2. **现有方法不足**：FinePDFs、CCpdf、PDFA等主流语料库仅公布文件级通过率或分类比例，未提供token权重的分布拆解；截断与过滤策略的影响也仅以文件占比衡量，未评估对实际可用文本的侵蚀。
3. **模型消费视角缺失**：语言模型以token为训练单元，文档级指标会严重掩盖长文档（论文、报告等）对高质量token的贡献，误导数据筛选与截断策略的设计。
4. **动机**：通过同一语料库的双视角（文档数/token数）对比，暴露统计口径偏差，并为语料库度量标准与网络爬虫的截断政策提供实证依据。

## 核心贡献（创新点）
1. **首次对Web-PDF语料库进行token权重化刻画**，直接对比文档数与token数下的各项headline statistic；与FinePDFs/CCpdf等仅报告文件级比率的工作相比，本文揭示了同一指标在不同计量单位下的巨大数值分裂。
2. **提出文本质量的极端集中性结论**（Gini 0.807，3.02%文档持有一半token）；与以往将语料视为同质文档集合的假设不同，本文证明长度偏态是Web-PDF的结构性特征而非提取器噪声。
3. **首次量化Common Crawl截断阈值的实际文本代价**（1 MiB导致55%–62%语料永久丢失）；与过往仅以文件占比描述截断影响的研究不同，本文指出基于字节大小的硬截断策略实际定价的是archive存储而非corpus可用性。
4. **开源完整的多引擎截断恢复评估代码**，提供可复现的“截断-重建-对比”度量框架，推动语料库审计标准化。

## 方法详解
1. **双单元统计框架**：以 CC-MAIN-2021-31-PDF-UNTRUNCATED（去重后7.93M文档，32.57B token）为基础，将页数分布、工具链来源、截断状态等指标分别以文档数占比与token数占比呈现，计算各类别的 token/doc 倍率。
2. **Token基准定义**：使用元数据字段 `tika_eval_num_tokens`（Apache Tika 2.8.0 空格/ICU分词，OCR禁用），仅用于比例计算；字段右截断上限为10,000,000，实际仅2个文档触及该上限。
3. **截断重建与对比提取**：利用 `cc_truncated` 与 WARC byte range 精确标记1.83M个被截断文档，在1 MiB处物理切分；同时保留重新获取的完整文件作为Ground Truth，对比完整文件与切分文件的提取结果。
4. **多解析器交叉验证**：在截断文件上分别运行 PyMuPDF（MuPDF）和 PDFium（pypdfium2），对比两者的打开率、页面恢复率与token恢复率，分离“文件结构损坏”与“解析器容错差异”两类误差源；并在完整文件上验证两引擎的一致性（偏差<1.7%）。
5. **固定前缀反事实评估**：将同一份完整文档分别在1 MiB与5 MiB处截断，对比两种阈值下的可恢复token比例，验证阈值升级的边际收益分布。
