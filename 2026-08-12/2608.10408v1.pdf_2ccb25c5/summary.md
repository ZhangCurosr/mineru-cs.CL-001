# 论文速读：VisEditBench: Can Vision-Language Models Edit Visualization Code from Multimodal Feedback?

## 一句话总结
本文提出了 **VisEditBench**，首个面向从多模态反馈编辑可视化代码的评测基准（1,395 个人工标注任务），涵盖反馈引导修复（feedback-guided repair）与参考引导重 stylization（reference-guided restyling）两类场景；同时设计了渲染反馈驱动的四步迭代编辑框架 **VisEditAgent**，在 GPT-4o 上将整体通过率从 55.75% 提升至 67.99%，揭示了当前 VLM 在视觉上忠实、语义一致的可视化代码编辑方面仍存在显著差距。

## 研究问题与动机
1. **真实可视化创作流程本质上是迭代的**：用户通常需要检查渲染图表、修改代码、重新渲染并反复微调，然而现有基准主要评估"从零生成"（from scratch），未能覆盖这一更常见的工作流。
2. **可视化代码编辑具有独特挑战**：需要局部修改以修复错误布局、重叠标签、误导性编码等，同时保持数据语义、图表结构和分析含义不变——这要求比一般代码生成更强的多模态推理与视觉 grounding 能力。
3. **现有基准均未覆盖该场景**：Text-to-Viz 基准聚焦自然语言→图表生成，Chart-to-Code 基准聚焦从图表图像重建代码，通用多模态软件工程基准（如 SWE-bench Multimodal）未涉及可视化特有的编码修复与风格匹配问题。
4. **即使可执行代码也非性能瓶颈**：Claude-4.6-Sonnet 以 96.19% 的代码执行成功率运行，但视觉相似度仅 89.42，说明模型常能生成"可跑"代码却无法产出符合视觉意图的结果。

## 核心贡献（创新点）
1. **提出 VisEditBench**：首个覆盖反馈引导修复与参考引导重 stylization 的可视化代码编辑基准，含 1,395 个高质量人工标注任务，覆盖 8 类编辑意图与多样化图表类型/难度。
2. **设计细粒度多维评测体系**：引入可执行性、任务准确率、可读性与清晰度、视觉质量、视觉相似度及最终通过率（综合阈值严格判定）六项指标，弥补了以往单一执行正确性评测的不足。
3. **提出 VisEditAgent 渲染反馈驱动框架**：通过多候选生成→执行渲染→视觉验证选择→反馈迭代精化的四步循环，将 GPT-4o 的整体通过率从 55.75% 提升至 67.99%，并大幅改善视觉接地编辑子任务的性能。
4. **系统性评测 20 个 SOTA VLM**：揭示当前最强模型（Claude-4.6-Sonnet，74.46%）仍远未达到可靠可视化编辑水平，开源模型普遍低于 50%，尤其在风格适配（最高仅 55.71%）等视觉协调任务上表现极弱。
5. **与人类评估的一致性验证**：自动评测器与 5 位标注者 Pearson 相关系数达 83.38–87.00，表明自动化评测高度可靠，支持大规模可扩展评估。

## 方法详解

### VisEditBench 数据集构建
- **数据来源**：① 手动收集 120 个来自 Stack Overflow 及 Matplotlib/Vega-Lite GitHub issue 的真实可视化问题案例；② 使用 Text2Vis 基准（数据来源含 Statista、Pew Research、Our World in Data、OECD），对当前模型生成的代码执行并人工检查渲染图表，保留存在视觉/语义/展示错误的样本。
- **标注流程**：4 位标注员创建初始 1,648 个候选任务，每位标注任务包含：原有可视化代码、图表图片、自然语言编辑指令、元数据（编辑意图、问题类型、库类型、图表类型）。另一标注员独立交叉审核，接受/拒绝一致率达 84.65%，最终保留 1,395 个任务。
- **编辑意图八类**：Correctness Repair（37.9%）、Quality Improvement（32.0%）、Robustness/Generalization（8.3%）、Style Adaptation（5.0%）、Refactor/Transformation（4.5%）、Consistency Harmonization（4.2%）、Constraint Satisfaction（3.7%）、Style-Aware Error Repair（3.5%）。
- **难度标注**：用 GPT-5 按固定评分标准标注为 Easy/Medium/Hard（37.0%/35.7%/27.3%），再经人工复核验证。
- **可视化范式覆盖**：1,156 个 Matplotlib（命令式）+ 239 个 Vega-Lite（声明式）任务，覆盖柱状图、折线图、散点图、箱线图、热力图等多种图表类型；57.1% 的任务为多原因（multi-cause），需协调修改多个图表组件。

### 任务形式化
每个样本表示为 $x_i = (c_i, I_i, u_i, c'_i)$，其中 $c_i$ 为输入可视化代码，$I_i$ 为渲染图表图像，$u_i$ 为自然语言编辑指令，$c'_i$ 为修订后的可执行代码。两种编辑设置：
- **反馈引导修复**（feedback-guided repair）：$I_i$ 为含错误或人工标记的图表，模型需根据文本反馈修复。
- **参考引导重 stylization**（reference-guided restyling）：$I_i$ 为目标风格参考图，模型需在不改变数据语义的前提下匹配参考样式。

### VisEditAgent 框架（四步迭代）
1. **Edit Planning（编辑规划）**：给定代码、图表、指令和编辑意图，识别视觉问题所在、相关代码区域及修改策略，实现视觉渲染与代码结构的双重 grounding。
2. **Candidate Generation（多候选生成）**：生成多个不同实现方式的候选代码编辑，分别执行并渲染成图表，同时评估程序级正确性和可视化级质量。
3. **Visual Validation and Selection（视觉验证与选择）**：基于任务指令、输入图表和参考图像，评估各候选是否满足编辑要求、保持数据语义且与目标视觉对齐，选出最优候选。
4. **Feedback-Based Refinement（反馈精化）**：利用执行诊断、渲染失败信息和视觉验证反馈对选中候选进行迭代改进，纠正一次性生成常见的失效模式。

### 评测协议
- **自动评测器**：采用固定提示的 rubric-based VLM 评测器（默认 GPT-4o；评测 GPT-4o 自身时使用 Gemini 2.5 Pro 避免自评偏差）。
- **打分体系**：任务准确率/可读性/视觉质量为 0–5 分（0.5 点递增）；视觉相似度为 0–100 分。
- **最终通过率（Final Pass Rate）严格判定**：需同时满足可执行=1、任务准确率≥4.5、可读性/视觉质量≥4.0、视觉相似度≥90。
- **推理参数**：image detail=high, temperature=0.2, top-p=1.0, max tokens=4096，输出格式为完整可执行代码（无 markdown）。

## 实验与结果

### 数据集规模与多样性
- 总计 **1,395** 个高质人工标注任务（从 1,648 候选中筛选，一致率 84.65%）。
- 多原因任务占比 **57.1%**（797/1,395），Hard 难度占比 **27.3%**。
- 图类型：柱状图 48.7%、折线图 37.4%、散点图 3.7%、箱线图 3.9%、其他 6.3%。
- 库类型：Matplotlib 82.9%（1,156）、Vega-Lite 17.1%（239）。

### 基线评测（20 个 VLM，zero-shot）
| 模型 | 整体通过率 | 正确性修复 | 风格适配 |
|---|---|---|---|
| **Claude-4.6-Sonnet** | **74.46%** | 70.34% | 55.71% |
| GPT-5 | 65.68% | 61.60% | 57.14% |
| Claude-4.5-Sonnet | 62.73% | 60.83% | 52.86% |
| GPT-5-Mini | 60.00% | 55.51% | 47.14% |
| Qwen3-VL-32B（最佳开源） | 51.72% | 54.95% | 21.42% |
| GPT-4o | 55.75% | 56.08% | 10.00% |
| InternVL-3.5-1B | 7.41% | 11.41% | 0.00% |

- Claude-4.6-Sonnet 执行成功率 96.19%，视觉相似度 89.42；GPT-4o 执行率 93.31%，视觉相似度仅 78.13，印证"可执行≠视觉忠实"。
- 风格适配是最大瓶颈，即使最强模型也仅 55.71%（GPT-4o 仅 10.00%）。

### VisEditAgent 效果
- **GPT-4o + VisEditAgent**：整体通过率从 55.75% → **67.99%**（+12.24pp）；风格适配从 10.00% → **62.85%**（+52.85pp）；一致性协调从 47.46% → 64.41%。
- **Qwen3-VL-4B + VisEditAgent**：从 38.84% → 44.98%；风格适配从 1.42% → 35.71%。
- **消融**：移除多候选生成，整体降至 61.94%（-6.05pp）；移除精化步骤，降至 59.86%（-8.13pp），风格适配分别降至 28.57% 和 41.43%。
- **人类评测**：与自动评测 Pearson 相关 83.38–87.00，Pass/Fail 一致率 81.00%。

### 主要错误模式（500 样本定性分析）
1. **可执行但视觉错误**：执行成功但未完成指定修改（如标签仍重叠、图例位置错误）。
2. **视觉反馈 grounding 弱**：无法精准定位需修改的图表区域，箭头指向错误数据点。
3. **参考风格匹配差**：在风格适配中做泛化改动，未能保留参考图的布局/颜色/字体。
4. **不完整或不正确变换**：重构任务中改错图表类型、遗漏必需视觉元素或改变数据语义。

## 相关工作脉络
1. **Text-to-Visualization 基准**（Text2Vis、VisEval、nvBench）：评估从文本/表格生成图表的能力，但不涉及已有代码的迭代编辑，与本文的核心区分在于是否提供"既有代码+多模态反馈"的编辑设定。
2. **Chart-to-Code 基准**（ChartMimic、Plot2Code、ChartLlama）：评估从图表图像重建代码，是单向的"图像→代码"任务，而本文强调"代码+图像反馈→修订代码"的双向迭代编辑过程。
3. **SWE-bench Multimodal**（Yang et al., 2024b）：多模态软件工程的视觉 bug 修复基准，但未覆盖可视化特有的误导性编码修复、布局拥挤解决及参考风格匹配等可视化专属挑战。
4. **UI-to-Code / SVG Editing**（Design2Code、SVGEditBench、MMCode）：关注界面截图→代码或 SVG 编辑，其视觉 grounding 重点在网页/SVG 布局而非统计图表的编码映射与数据分析语义保持。
5. **ChartBench**（Xu et al., 2023）：专注图表理解与视觉推理问答，不涉及代码编辑层面。
6. 本文与上述工作的本质差异在于：**首次在真实可视化编辑工作流下，以多模态反馈驱动的代码修订为核心任务，兼顾可执行性与视觉语义忠实性**。

## 局限性与未来方向
1. **仅覆盖两个可视化库**：当前仅支持 Matplotlib 和 Vega-Lite，未包含 Plotly、D3.js、ggplot2 等广泛使用的生态系统，模型表现是否泛化至其他库未知。
2. **任务类型未穷尽**：虽涵盖常见编辑场景（布局调整、标签修复、编码纠正、风格适配等），但未覆盖专业领域特定的约束、约定或可视化类型。
3. **难度标注依赖 GPT-5**：难度分级由 GPT-5 完成并经人工复核，可能存在主观偏差。
4. **未来方向**：扩展至更多可视化库和领域；探索更强的渲染反馈迭代机制；将 VisEditAgent 框架推广至更广泛的视觉编程编辑任务。

## 研究启发与可借鉴点
1. **渲染反馈驱动迭代编辑框架可迁移**：VisEditAgent 的"多候选生成→执行渲染→视觉验证→精化"四步循环可直接迁移到 UI 代码编辑、SVG 编辑、Dashboard 构建等需要视觉保真度的领域，核心思想是用真实渲染输出作为 grounding 信号而非仅依赖模型自身判断。
2. **严格的多维综合通过率（Final Pass Rate）值得借鉴**：同时要求可执行性+高任务准确率+可读性+视觉质量+高视觉相似度，避免了"部分正确但不可用"的虚假高性能，可作为可视化/AI 辅助编程评测的通用严格标准。
3. **多候选探索对视觉接地任务至关重要**：消融实验证明移除多候选生成后风格适配性能从 62.85% 骤降至 28.57%，说明视觉编辑任务存在多解性，候选多样性探索是关键机制——可借鉴到任意视觉生成/编辑工作流中。
4. **自动化评测与人类评估高一致性（Pearson 83–87%）**：Rubric-based VLM 自动评测器的设计（固定提示、严格阈值、避免自评偏差）可有效替代大量人工标注，为大规模可视化评测提供了高效可行的方案。
5. **与团队方向的潜在结合点**：若团队涉及代码生成/视觉理解方向，可将 VisEditBench 的迭代反馈范式与强化学习/视觉 grounding 方法结合，探索"基于渲染反馈的代码修正 RL 训练"或"多候选视觉对齐损失"等新方向。

## 关键术语表
**VisEditBench**：首个面向从多模态反馈编辑可视化代码的评测基准，包含 1,395 个人工标注任务，覆盖反馈引导修复与参考引导重 stylization 两类设置。

**Feedback-guided repair（反馈引导修复）**：用户提供带错误或人工标记的渲染图表及文本反馈，模型需修改现有可视化代码以修复问题，同时保持数据语义不变。

**Reference-guided restyling（参考引导重 stylization）**：用户提供目标参考图表图像，模型需修改原代码使其视觉风格与参考图匹配，不改变底层数据语义。

**VisEditAgent**：一种基于渲染反馈的迭代编辑代理框架，通过多候选生成、执行渲染、视觉验证选择和反馈精化四步循环提升可视化代码编辑性能。

**Final Pass Rate（最终通过率）**：严格的综合评分阈值——要求代码可执行、任务准确率≥4.5/5、可读性≥4.0/5、视觉质量≥4.0/5、视觉相似度≥90/100，四项同时满足才算通过。

**Visual Similarity（视觉相似度）**：0–100 分度量，根据编辑意图类型（修复/风格适配/风格感知修复等）采用不同的参照比较规则。

**Editing Intent（编辑意图）**：VisEditBench 定义的八类编辑目标分类，包括正确性修复、质量改善、鲁棒性增强、风格适配、重构/变换、一致性协调、约束满足和风格感知修复。

## 可复现要素
- **数据集**：VisEditBench 将于 https://github.com/vis-nlp/VisEditBench 开源（论文声明）。
- **代码/权重**：论文未提及开源代码仓库（VisEditBench 仓库地址已公布但代码未说明是否同步发布）；VisEditAgent 为框架描述，未提及开源。
- **关键超参**：推理参数：image detail=high, temperature=0.2, top-p=1.0, max output tokens=4096；评测器参数：temperature=0.0, max tokens=1200, image detail=high；最终通过率阈值：任务准确率≥4.5、可读性≥4.0、视觉质量≥4.0、视觉相似度≥90。
- **渲染环境**：Vega-Lite 使用 vl-convert-python 渲染，Python/Matplotlib 使用非交互 Agg backend。
- **评估器**：默认 GPT-4o；评测 GPT-4o 自身输出时改用 Gemini 2.5 Pro 避免自评偏差。
