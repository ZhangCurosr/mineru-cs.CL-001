# 论文速读：DSAgentBench: Can Agents Automate End-to-End Data-Science Workflows in Real Computer Environments?

## 一句话总结
本文提出首个在真实操作系统环境中评估智能体执行端到端数据科学工作流能力的基准测试 DSAGENTBENCH，涵盖数据获取、探索性分析、特征工程、建模、评估与可视化全生命周期。实验揭示当前最强智能体（Claude-4.6-Sonnet）仅达 56.70% 成功率，开源智能体普遍低于 1%，暴露出系统在真实环境接地、工具编排与长程推理方面的显著能力缺口。

## 研究问题与动机
- **核心问题**：当前 AI 智能体能否在真实计算机环境中自主执行端到端数据科学工作流？
- **现有方法不足**：
  1. 既有数据科学基准（如 DS-1000、DABStep、MLAgentBench）仅评估孤立代码执行，缺乏真实操作系统交互、跨工具协调与多阶段迭代推理。
  2. 既有 GUI 智能体基准（如 OSWorld、WebArena）侧重通用桌面控制，未要求执行数据分析、模型训练与可视化产出等数据科学核心任务。
  3. 现有评估多依赖静态代码执行或表面语法正确性，无法验证分析结论的语义正确性、可视化质量与模型性能指标。
  4. 数据科学实践需要协调笔记本、IDE、终端、浏览器与数据库等多工具，并基于中间输出持续调整策略，现有基准未能建模此复杂性。

## 核心贡献（创新点）
1. **首个面向真实 OS 环境的数据科学智能体基准**：DSAGENTBENCH 首次允许智能体在完整 Ubuntu 桌面中自主执行从数据获取到报告生成的端到端工作流，而非仅在沙箱代码环境中运行脚本。
2. **OSWorld 扩展以支持数据科学关键工具链**：集成 Jupyter Notebook、VS Code、Chrome 浏览器及 Kaggle API、OpenML、SQLite 等外部数据源，构建贴近工业实践的动态执行环境。
3. **确定性、多维度的输出验证评估器**：不仅检查代码是否执行成功，还通过规则验证数值精度、可视化语义对齐（轴标签、图例、数据映射）及模型性能阈值（如 F1 ≥ 0.7），部分任务辅以 LLM 视觉评委进行定性评估。
4. **系统性全面评测与深度失败分析**：对 15 个闭源/开源智能体进行广泛实验，结合错误归因与轨迹时序分析，定位当前系统在接地、编排、代码生成与逻辑推理等环节的关键瓶颈。
5. **完全开源与可复现设计**：所有 275 个任务、确定性评估脚本、环境配置与模型推理代码均已开源，支持跨操作系统（Linux/Windows/macOS）的端口化部署。

## 方法详解
- **环境架构**：基于 OSWorld 框架，运行 Ubuntu 虚拟机（分辨率 1920×1080），预装 Python、数据科学库、VS Code、Jupyter Notebook 与 Chrome。智能体通过截图（Screenshot）或截图+无障碍树（A11y Tree）两种模态观察环境，并通过统一动作空间执行鼠标点击、键盘输入、滚动等 GUI 操作。
- **任务形式化**：每个任务定义为三元组 (C_i, I_i, V_i)，其中 C_i 为环境配置（数据集、文件结构、应用状态），I_i 为自然语言指令，V_i 为确定性 Python 评估器。任务成功当且仅当智能体产出满足 V_i 的终态工件（如 CSV、图表、模型文件）。
- **数据集构建**：汇集 Kaggle、OpenML、SQLite、GitHub 与 Web API 等多源异构数据，覆盖表格（95.3%）、图像（3.6%）与文本（1.1%）模态。275 个任务由具备五年以上经验的数据科学专家人工设计，经双标注员独立审核与执行验证，初始一致性达 86%。
- **评估协议**：主指标为任务成功率（得分 ≥ 0.95 的比例），同时报告平均评估分数。评估器组合确定性规则（文件存在性、数值容差 ϵ=0.01、图表元数据检查）与 LLM 评委（如 Gemini-2.5-Pro 评估 GPT-4o 输出，避免自我评估偏差）。
- **智能体生态**：测试模型包括 GPT-4o、GPT-5、Claude 系列、Gemini-2.5-Pro、OpenAI CUA 及 UI-TARS、GUI-OWL、OpenCUA、Jedi 等开源视觉 - 语言智能体，涵盖统一架构与混合架构。

## 实验与结果
- **数据集**：275 个长周期任务，复杂度分布：Hard 47.6%、Medium 46.9%、Easy 5.5%；56.7% 为多阶段工作流，平均 4–5 步分析操作。
- **评估基线**：15 个主流视觉 - 语言智能体（8 个闭源、7 个开源），在 Screenshot 与 Screenshot+A11y Tree 两种设置下评测。
- **主要结果**：
  - 最强闭源智能体 Claude-4.6-Sonnet 在 Screenshot+A11y Tree 设置下取得 56.70% 整体成功率，EDA 类别达 64.88%，Visualization 类别达 42.42%。
  - GPT-5 整体准确率 29.81%，GPT-4o 为 24.54%，Gemini-2.5-Pro 为 20.81%。
  - 所有开源智能体在 Screenshot 设置下整体成功率均低于 1%，主要因接地失败（UI-TARS 98.18%、GUI-OWL 97.09%）。
  - 人类参考表现达 85.09% 整体成功率。
- **关键结论**：当前智能体在长程推理、跨工具协调与真实环境接地方面存在显著能力缺口；A11y Tree 辅助可提升部分模型性能但收益有限；增加步数预算（15→50 步）仅带来边际改善（24.54%→25.81%），表明瓶颈非行动数量而是推理与编排能力。

## 相关工作脉络
1. **数据科学代码生成基准**：DS-1000、DABStep、MLAgentBench、DSBench、DSEval 等仅评估静态代码执行正确性，不涉及真实 OS 交互或多工具协作，本文在此基础上引入端到端工作流与确定性语义评估。
2. **数据分析流水线基准**：DA-CODE、KRAMABench、ARCADE 虽覆盖更复杂分析阶段，但仍局限于沙箱 notebook 环境，缺乏操作系统级 grounding 与跨应用协调能力。
3. **GUI 智能体基准**：OSWorld、WebArena、VisualWebArena、AndroidWorld、OfficeBench 等聚焦通用桌面控制与界面导航，未要求执行数据分析、模型训练与可视化产出等数据科学专属任务。
4. **可视化与报表基准**：ChartQA、Text2Vis、VisEval、DashboardQA 主要评估图表生成或视觉问答，缺乏与数据预处理、特征工程、模型评估等环节的端到端整合。
5. **视觉语言 GUI 智能体**：CogAgent、ShowUI、Ferret-UI、OS-ATLAS、JEDI、GUI-R1、GUI-G2、InfiGUI-G1 等提升 GUI 接地与交互能力，但本文揭示其在真实数据科学任务中仍因分析推理与工具编排短板而表现惨淡。

## 局限性与未来方向
- **开源模型评估限制**：当前开源智能体不支持 A11y Tree 输入，仅能在 Screenshot 设置下评测，可能低估其潜力。
- **误差分析样本有限**：深度错误分析基于 604 条闭源与 150 条开源轨迹，稀有失败模式可能未被充分捕捉。
- **可视化评估侧重终态质量**：评估器主要验证最终图表/报告的语义正确性与元数据完整性，对生成过程中的迭代调试与交互探索关注不足。
- **环境泛化性**：实验主要在 Ubuntu 上进行，虽声称可移植至 Windows/macOS，但实际跨平台表现有待验证。
- **未来方向**：开发增强 grounding 与规划能力的新一代智能体；支持更多数据科学工具（如 R/RStudio、PyCharm）；探索强化学习在长程工作流优化中的应用；构建更具挑战性的多模态与动态数据源任务。

## 研究启发与可借鉴点
1. **确定性评估器设计**：将数值容差、文件存在性、元数据校验与 LLM 评委分层结合的方法，可为其他复杂工作流基准（如科学计算、工程仿真）提供评估范式参考。
2. **A11y Tree 融合观察模态**：在视觉观测中集成结构化 UI 元数据可显著提升接地精度，该设计可直接迁移至其他 GUI 智能体任务。
3. **任务难度与阶段类型多维划分**：按步骤数（1-2/3-4/5+）、工作流阶段（单步/多步）、工具数量与数据模态构建多样性基准，有助于细粒度诊断模型能力边界。
4. **失败模式时序分析**：引入首次失败步骤（FF）、预算耗尽率、恢复率等轨迹指标，可精准定位智能体在长程执行中的薄弱环节，为算法改进提供诊断依据。
5. **人机对比基线**：设置人类专家 Performance 参考线（85.09%），使基准评测更具现实意义与进步导向性。

## 关键术语表
- **DSAGENTBENCH**：首个在真实操作系统环境中评估智能体端到端数据科学工作流能力的基准测试，包含 275 个人工设计任务。
- **OSWorld**：用于构建多操作系统 GUI 智能体基准的开源框架，本文以其为基础扩展数据科学专用工具与数据源。
- **A11y Tree**：Accessibility Tree，通过 AT-SPI 提取的结构化 UI 元数据树，包含元素角色、名称、边界框与交互状态，辅助智能体精准接地。
- **确定性评估器**：基于预定义规则与容差阈值的自动化评分脚本，不依赖 LLM 即可验证数值结果、文件输出与可视化语义。
- **端到端数据科学工作流**：涵盖数据获取、清洗、探索性分析、特征工程、建模、评估与可视化报告生成的完整分析生命周期。
- **多阶段任务（Multi-Stage）**：需要智能体迭代执行多个分析步骤、基于中间输出调整后续操作的任务类型，占基准 56.7%。
- **视觉语言智能体（Vision-Language Agent）**：融合视觉感知与语言理解的大模型智能体，通过截图观察环境并生成 GUI 控制动作。
- **首次失败步骤（First Failure, FF）**：智能体执行轨迹中检测到错误的最早步骤，用于分析失败发生时机与轨迹结构。

## 可复现要素
- **数据集**：275 个任务及全部数据集已开源，托管于 https://github.com/vis-nlp/DSAgentBench。
- **代码**：环境配置、评估脚本、智能体推理代码与系统提示均已公开。
- **关键超参**：屏幕分辨率 1920×1080；动作空间基于 PyAutoGUI；温度固定为 0.1；top-p 为 0.9；最大步数预算 15（消融实验扩展至 30/50）；任务超时 1800 秒；动作后延迟 2.0 秒。
- **开源模型依赖**：vLLM 推理引擎（GCP n1-standard-4 + GPU 实例）；闭源模型通过官方 API 访问。
- **环境可移植性**：支持 Ubuntu/Linux、Windows、macOS，可通过适配配置部署至其他 OSWorld 兼容平台。
