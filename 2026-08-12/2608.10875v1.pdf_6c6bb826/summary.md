# 论文速读：VibeLifeBench: Can Your Life Agent Be Proactive and Persistent in a Living World?

## 一句话总结
论文提出VibeLifeBench，一个包含200个长周期任务的基准测试，用于评估LLM代理在日常生活中的主动性和持久性；测试发现当前最前沿模型平均分仅约32分，表明现有代理距离真正可靠的生活助手仍有巨大差距。

## 研究问题与动机
1. **现有评估与真实生活场景错位**：当前benchmark主要关注编程、办公等职业场景，忽视日常生活中用户最需可信协助的场景。
2. **被动执行vs主动感知**：现有方法测量代理被动执行明确指令的能力，而非其自主判断何时行动、何时保持沉默的主动性。
3. **静态环境vs动态世界**：现有环境不独立变化，无法评估代理对自发变化的感知和响应能力。
4. **单任务vs长周期连贯性**：现有任务多为孤立单任务，缺乏覆盖完整生命周期、具有复杂依赖关系的长周期任务。

## 核心贡献（创新点）
1. **重新定义评估维度**：将主动性、动态世界适应、长周期连贯性三个未被充分测量的现实协助属性整合到单一评估框架中，区别于此前工作仅关注单任务或静态环境的局限。
2. **构建VibeLifeBench基准**：创建200个跨10个日常生活领域的多周任务，基于22个模拟服务后端（288个工具接口）和7,453个脚本事件，其中1,483个为静默突变，区别于现有benchmark依赖显式通知的机制。
3. **设计细粒度加权评分体系**：开发12,261个分层检查点（含阶段性、跨阶段、最终三层），通过权重设计确保安全性检查比常规子任务更重要，区别于简单完成度评分。
4. **揭示前沿模型的普遍不足**：评估7个前沿模型发现最高分仅32.5，证明现有工具调用能力无法自动迁移到长期主动生活协助场景。

## 方法详解
**任务形式化定义**：每个任务表示为五元组 $\tau = (W_0, \mathcal{E}, \mathcal{K}, P, R)$，其中 $W_0$ 为初始世界状态，$\mathcal{E}$ 为事件时间线，$\mathcal{K}$ 为启用的服务集合，$P$ 为角色与工作空间，$R$ 为加权检查标准。

**世界演化机制**：
- 世界状态按公式 $W_j := \text{apply}(W_{j-1}, e_j, a_j)$ 更新，其中 $a_j$ 为代理动作序列
- 突变事件(mutation)直接修改世界状态且不产生代理回合，这是可测量主动性的核心机制

**四种事件类型**：
1. User message：触发代理回合的用户消息
2. World observation：外部服务状态报告，进入观察层
3. Notification：系统或频道推送
4. Mutation：静默背景变更，不触发代理回合，仅改变世界状态

**评分架构**：
- 三个阶段检查：per-stage（及时性）、cross-stage（跨阶段一致性）、final（最终状态）
- 五种证据维度：工具调用、后端最终状态、持久化产物、回复一致性、跨阶段一致性
- 权重不均设计：安全检查权重远超常规任务，防止代理通过完成大量子任务掩盖安全风险

## 实验与结果
**数据集**：200个任务均匀分布在10个领域（travel/finance/litigation/renovation/career/fitness/exam preparation/rental/shopping/team building），每个领域20个任务。

**基线与模型**：评估7个前沿模型：Claude Opus 5、GPT-5.5、Gemini 3.5 Flash、Claude Opus 4.8、GLM-5.2、Kimi-K2.6、DeepSeek-V4-Pro。

**核心结果**：
- 最强模型Claude Opus 5：avg@3 = 32.5，max@3 = 41.2
- 最弱模型DeepSeek-V4-Pro：avg@3 = 21.1
- 所有模型处于21-33分的窄带内，与胜任水平差距巨大
- 跨领域表现差异大：shopping领域最高51.1（GPT-5.5），team building最低10.5（Kimi-K2.6）

**成本分析**：
- 模型输出token数与得分正相关但不绝对：Gemini 3.5 Flash读取最多上下文(41.2M)却仅排中游
- 关键不在投入量而在于状态持久化和约束遵守方式

**失败模式分析**：
- 跨阶段和最终检查通过率最低（26-33%），这些检查占19.1%但权重占26.8%
- 主动性和持久性是最弱能力维度：所有模型在此维度得分不超过33.6
- 持久性与记账失败占所有失败检查的22.2%，且各模型表现稳定
- 时间线上后三分之一的通过率比前三分之一下降10-15个百分点

## 相关工作脉络
1. **SWE-Milestone/Terminal-Bench**：编程/终端场景benchmark，专注单任务一次性执行，世界仅随代理动作变化，与VibeLifeBench的长期动态世界形成对比。
2. **APEX-Agents/JobBench/Workspace-Bench**：办公知识工作benchmark，测量被动执行能力，缺乏主动性评估和独立演化的环境。
3. **ClawBench/UniclawBench**：网页/计算机使用benchmark，虽涉及日常生活但非多周持续任务，且无静默世界变更机制。
4. **UltraHorizon/Continual Learning Bench**：长周期评估尝试，但通常在任务间变化而非任务内独立演化，目标仍为显式指令执行。
5. **ClawMark/ClawArena**：多轮多日benchmark，接近但缺乏1,483个静默突变的设计，无法精确测量"无通知下的主动重检"能力。
6. **CostBench**：聚焦工具调用成本优化，非生活场景的长期主动行为评估。

## 局限性与未来方向
1. **领域覆盖有限**：仅涵盖10个预设日常生活领域，实际生活场景更复杂多样。
2. **模拟服务局限**：22个mock服务虽保证可复现性，但无法完全替代真实服务的复杂性和不确定性。
3. **模型评估局限**：仅评估7个前沿模型，未探索不同架构设计（如memory机制、agent框架）的影响。
4. **评分标准主观性**：虽然检查是确定性的，但人工编写check和权重设计可能存在偏差。
5. **改进方向**：需要显式持久化状态到notes/calendar/workspace、主动感知和传播突变、加强安全性和授权边界遵守、提升长周期稳定性。

## 研究启发与可借鉴点
1. **静默突变机制**：将环境变更与通知解耦的设计，为评估主动感知能力提供了可量化方案，可迁移至其他需要评估"未请求时行动"的场景。
2. **分层加权评分**：三阶段（per-stage/cross-stage/final）+ 不均匀权重的设计，有效区分"完成"与"高质量完成"，适用于评估复杂长期任务。
3. **隐性约束嵌入**：在persona和workspace中植入未明说但必须遵守的约束（如budget cap、安全红线），测试代理的真实理解而非表面顺从。
4. **通用服务后端复用**：22个服务后端供200个任务共享的设计，平衡了场景多样性和评估可复现性，值得在大规模benchmark中借鉴。
5. **主动性与持久性的解耦测量**：分别量化"何时行动"和"保持状态一致"，为agent能力诊断提供细粒度信号。

## 关键术语表
**Proactivity（主动性）**：代理在无提示时自主决定何时行动、何时通知用户、何时保持沉默的能力。
**Living World（动态世界）**：独立于代理动作、按自身时钟演进的环境，包含静默变更和未通知事件。
**Long-horizon（长周期）**：任务跨越数周到数月，需要代理在多阶段维持计划一致性和约束遵守。
**Mutation（突变）**：不触发代理回合的静默环境变更，用于测试代理主动重检世界状态的能力。
**Cross-stage check（跨阶段检查）**：验证整个任务期间必须保持一致的约束（如预算上限、安全红线）的检查。
**Persona/Workspace（角色/工作空间）**：赋予代理的背景信息，包括用户身份、偏好、隐性约束和授权边界。
**Token cost（token成本）**：衡量代理完成任务所需的输入/输出token量、工具调用次数和回合数。
**Hardening/Safety（硬化/安全）**：测试代理拒绝钓鱼邮件、保护个人数据、遵守授权边界的检查维度。

## 可复现要素
- **数据集**：200个任务，论文声明将开源所有任务、环境和评估框架
- **代码/框架**：基于TERRARIUM基础设施[16]（开源，https://github.com/evolvent-ai/Terrarium），使用openclaw harness
- **服务后端**：22个mock服务，288个工具接口，全部离线可复现
- **超参数**：每个任务运行3次，报告avg@3/max@3/min@3；所有模型使用最强推理设置和原生工具调用脚手架
- **评分**：12,261个加权检查点，median 58个/任务，0-100分制
