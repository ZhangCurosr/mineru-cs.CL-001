# 论文速读：ENTLORE: A Graph-Grounded Benchmark for Latent Organizational Reasoning in Enterprise Question Answering

## 一句话总结
ENTLORE 提出了一个图基基准构建框架，从企业日常文档、权威组织表和运营记录中重建经审计的企业世界，将问答能力分解为显式查找（L1）、跨源组合（L2）和**隐性组织推理（L3）**三个层级；核心目标是评估系统在目标关系未被任何发布文档直接陈述的情况下，能否从分散证据中恢复隐含的组织关系。实验表明，即使提供金标准文档，仍有 30.4% 的 L3 问题无法回答。

## 研究问题与动机

1. **现有基准的"预设推理路径"缺陷**：当前企业 QA 基准（如 EnterpriseRAG-Bench、QO-Bench）通过将每个推理步骤材料化为显式文档内容来构建，测试的是对已陈述事实的检索与组合，而非从未见来源中恢复目标关系的**隐性组织推理**能力。
2. **企业日常记录的"副产品"本质**：企业内部文档（报告、工单、模块记录等）是日常工作副产品，组织关系（项目归属、职责分配、别名映射）通常隐含于异构来源之间，不存在单一的显式答案链。
3. **基准构建的可答性问题**：真实企业问题不一定能从发布资料中得出完整答案（结构前提可能为私有、可见记录仅覆盖部分答案）。直接从文档生成问题虽避免此不确定，但无法建立真实企业问题的完整且唯一的答案。
4. **检索能力与推理能力的混淆**：既有评测难以区分系统是在"找到相关文档"还是在"从文档中推导出隐含关系"，缺乏将两者分离的可评估设置。

## 核心贡献（创新点）

1. **形式化隐性企业过程 QA 并识别"隐性组织推理"为核心能力**：提出 L1/L2/L3 三级能力分解，将证据使用能力与组织关系恢复能力分离，现有基准均未明确评估后者。
2. **从真实企业文档构建经审计的真值图（truth graph）**：区分原生关系（native）、元数据关系（metadata）、启发式关联（heuristic）和经人类授权认证的派生关系（certified derived），现有工作仅使用材料化知识或显式规则。
3. **图基构建框架，联合确定可答性、完整金答案、证明依赖与发布锚定状态，且不暴露实例级金关系**：框架先生成私有审计世界，再投影为匿名化发布语料，目标关系始终对评测系统隐藏；相比 QO-Bench 等仅在物化知识上操作，本文在关系本身被 withholding 的情况下建立可验证答案。
4. **构建 ENTLORE（2,341 文档 / 907 问题 / 56 配置）并完成系统性评测**：覆盖 8 个模型 × 7 种访问范式，揭示 L3 残差（30.4%）远大于 L1/L2 残差的结构性差距。

## 方法详解

**四阶段构建流程**：

1. **重建原始图（G_raw）**：从三类企业来源（日常文档、权威组织表、运营轨迹）中抽取人物、项目、模块、活动、系统和客户实体，每条边保留来源溯源。原生关系来自文档/轨迹，元数据关系来自权威记录，启发式关联仅辅助候选发现和干扰项构建。

2. **认证组织惯例（Organizational Conventions）**：版本化的惯例库产生候选派生边。每条保留边记录其生成规则、依赖链和人工授权裁决。真值图为：
   $$G_{\text{truth}} = \text{audit}(G_{\text{raw}}) \cup \mathcal{C}^*(G_{\text{raw}})$$
   其中 $\mathcal{C}^*$ 表示经认证的规则应用（非无限制闭包）。示例惯例——包含传递：
   $$\mathtt{works\_on}(p, m) \circ \mathtt{contains}(\mathtt{proj}, m) \Rightarrow \mathtt{attributed\_to}(p, \mathtt{proj})$$

3. **匿名化发布投影**：共享匿名映射 $\phi$ 生成发布文档集 $D_{\text{release}}$，一致替换私有实体和别名并平移日期（保持相对组织不变）。评测系统仅访问 $D_{\text{release}}$，私有组织记录、真值图、认证规则和实例级证明均被隐藏。

4. **可执行图程序编译问题**：每道题由类型化图算子采样 $G_{\text{truth}}$ 中的合法区域、执行查询、记录类型化答案、证明依赖和关联的发布证据单元；LLM 仅实现表面措辞。按目标关系在发布证据中的表示分为：
   - **L1（显式查找）**：答案在单一发布文档中直接陈述
   - **L2（显式组合）**：答案由多个发布来源中的显式事实组合而成
   - **L3（隐性组织推理）**：目标关系在任一发布来源中均不存在，需从发布语料中隐含的组织结构中恢复

**验证管道（12 道闸口）**：版本锁定 → 来源合法性（每个不可或缺的前提须锚定于发布文档）→ 规则认证 → 谓词级前提锚定 → 公有/私有分离 → 目标关系在发布中不存在 → 精确覆盖 → 唯一性与闭包 → 原始忠实度 → 隐私筛查 → 问题清洁度 → 原始-发布重放。

## 实验与结果

**数据集规模**：2,341 篇发布文档（三类来源），907 题（L1=469, L2=204, L3=234），组织图 1,153 实体 / 3,784 类型化关系，平均每题需 2.53 篇金标准文档。

**评测配置**：8 模型（GPT-5.4/5.4-mini, Claude-Sonnet-4.6, Qwen3.5-397B-A17B, GLM-5.2, Kimi-K2.6, DeepSeek-V4-Pro/Flash）× 7 访问范式（Closed-book / BM25 / Flat RAG / Agentic / LLM-Wiki / GraphRAG / Ω）。

**主要结果（Table 1，平均值）**：

| 等级 | 最强部署条件 | 准确率 | BM25 | LLM-Wiki | GraphRAG |
|------|------------|--------|------|----------|----------|
| L1 | GraphRAG | 63.2% | 62.4% | 61.7% | — |
| L2 | LLM-Wiki | 52.5% | 51.4% | — | 52.2% |
| L3 | GraphRAG | **36.2%** | 34.0% | 27.7% | — |

- **Flat RAG 和 Agentic 全面落后**：三级加权均值仅 36.0%/36.5%，显著低于 BM25(52.6%)、GraphRAG(52.2%)、LLM-Wiki(50.9%)。
- **L3 残差分析**：在 Ω（提供金标准文档路径，同 agentic 工具循环）条件下，L1 残差 12.6%、L2 残差 6.2%、**L3 残差 30.4%**（是 L2 的 4.9 倍），说明文档检索误差并非 L3 失败的主因。
- **关系家族差异巨大**：部门归属（Department attribution）GraphRAG 达 53% vs BM25 仅 2%；而包含传递（Containment attribution）和层级汇总（Hierarchy rollup）所有部署条件均 <34%。
- **BM25 vs Dense 差距集中在文档组装环节**：当两个 flat retriever 均组装出完整金标准文档集时，BM25=75.7% vs Dense=72.1%（仅贡献 8% 差距）；当仅 BM25 组装出时贡献 71% 差距。
- **发布保真度**：粗粒度结构转移（top-3 oracle 顺序不变），但细粒度排序未达显著（Spearman ρ=0.71, p=0.06）。

## 相关工作脉络

1. **TechQA / doc2dial / MultiDoc2Dial / EKRAG / WixQA / EnterpriseRAG-Bench**：强调多源真实语料和检索生成，但答案均基于发布资料中**显式陈述**的事实；本文进一步要求从发布资料中**不存在**的关系推导答案。
2. **HotpotQA / 2WikiMultiHopQA / MuSiQue / KILT**：多跳 QA 基准将显式支撑事实分布到多篇文档中，测试显式事实的组合能力；本文 L3 目标关系不在任何发布文档中，属于不同难题。
3. **KQA Pro / ProofWriter / QO-Bench**：可执行程序基准在物化知识或类型化事件元组上运行确定性推理；QO-Bench 最接近本文的可执行视角，但目标为数据库式操作而非组织特有派生关系。
4. **DPR / RAG / FiD / IRCoT / ReAct / RAPTOR / Self-RAG**：检索增强架构改进文档召回与生成；本文将其作为评测对象而非方法贡献。
5. **HippoRAG / G-Retriever / GraphRAG / CRAG**：图结构利用方法；GraphRAG 在本文评测中表现最佳（L3=36.2%），但本文强调现有方法本身不能提供基准侧的"未被发布关系的认证"，二者互补。
6. **FinQA / TAT-QA / MultiHiertt / ARQA / MuDABench**：金融文档基准侧重表格-文本联合推理和数值计算；本文聚焦组织关系推导而非数值推理。

## 局限性与未来方向

1. **L3 评分近乎全有或全无**：GraphRAG 下 49% 的 L3 项得分为 0，23% 得分为 1，部分信用在集合答案中极少，整体 36.2% 的准确率意味着约半数完全错误、约四分之一完全正确。
2. **指令张力问题**：Oracle prompt 要求"仅使用已读内容"，而 L3 答案在构造上不存在于任何文档中，导致约 19.5% 的 L3 零分回答中模型声明"事实不存在"；8 道 PROJECT_HEADCOUNT 计数题所有模型零分，应改写或删除。
3. **发布保真度仅在群体层面成立**：细粒度排序未达统计显著，BM25 偏差（-0.28）可能与匿名化后的中文分词和别名标准化有关。
4. **惯例库覆盖有限**：当前聚焦 5 类已认证关系家族（包含传递、层级汇总、人员桥梁、工单角色语义、部门归属），聚合、足迹、交接和时间窗口为次要家族。
5. **未来方向**：扩展惯例家族、构建前提匹配的控制臂（同一基础前提在三级别间升级）、改进 L3 计数题措辞、将隐含组织关系恢复作为一等推理对象纳入系统架构。

## 研究启发与可借鉴点

1. **L1/L2/L3 三级能力分解框架可直接迁移**：将"显式证据使用"与"隐性关系恢复"分离的思路适用于其他需要跨源推导隐含关系的领域（如法律案例推理、医学文献综合）。
2. **Ω 黄金文档参考的残差分解（Δ_Ω 和 ρ_Ω）是有价值的诊断工具**：将总误差拆分为"访问间隙"和"残留误差"，可帮助定位系统瓶颈是在检索还是在推理，可复用于其他检索增强系统的深度分析。
3. **图基构建而非问题塑造文档的方式值得借鉴**：先生成完整私有世界再投影发布的思路，可解决现有基准"问可答但非真实"的生态效度问题，适用于需要严格隐私保护的数据集构建。
4. **匿名化发布+共享映射的隐私保护设计**：在保持跨源身份一致性和时间结构的同时移除身份信息，提供了企业场景数据发布的可复用模板。
5. ** inducing 图结构（GraphRAG）vs 扁平检索的效率对比发现**：Lexical retrieval（BM25）在某些企业场景中接近甚至超过 dense retrieval，挑战了"dense always better"的假设；启示后续工作应做更细粒度的访问范式消融。

## 关键术语表

**Latent Organizational Reasoning（隐性组织推理）**：从分布在不同异构来源的分散证据中恢复未在任何来源中直接陈述的组织关系（如项目归属、职责分配）的能力。

**Audited Truth Graph（审计真值图）**：由原始关系图经版本化组织惯例认证后形成的可信图，区分原生关系、元数据关系、启发式关联和已认证派生关系四类边。

**Organizational Conventions（组织惯例）**：编码组织知识的私有类型化规则库（如"工作于模块→模块属于项目→该人归属于项目"），用于认证从观察到关系的派生，不对外发布。

**Ω（Omega，黄金文档代理参考）**：向模型暴露金标准文档路径但通过相同 agentic 工具循环读取的 oracle 条件，消除检索召回误差但保留导航、交互和答案生成效应。

**Release-Fidelity（发布保真度）**：匿名化发布语料在保持私有源世界比较行为方面的一致性程度，本文验证了群体层面但细粒度排序不确定。

**Typed Graph Programs（类型化图程序）**：绑定问题到图算子的可执行查询，计算类型化答案、证明依赖、完整性和唯一性，是问题语义的正式化表示。

**Verified Abstention Bank（已验证弃权库）**：包含需不可缺少的私有前提的候选问题的蓄水池，这些项不在发布基准中但保留了完整性信息。

**Proof Certificate（证明证书）**：每条已认证派生边携带的结构化元数据 $(r, \text{rule\_id}, \text{rule\_version}, E_{\text{premise}}, E_{\text{release}}, v)$，含人工授权裁决。

## 可复现要素

- **数据集**：ENTLORE 基准（2,341 文档 / 907 题），发布于 arXiv:2608.10679v1；论文声明"benchmark, data, and code will be made publicly available"，Code and Data Supplement 含完整发布语料和题集、预处理代码、评测访问实现、提示词、评分和分析代码，发表后以 MIT License 开源。
- **代码/权重**：代码与数据将在发表后开源；模型权重为商用/开源大模型（GPT/Claude/Qwen/GLM/Kimi/DeepSeek），非本文贡献。
- **关键超参**：Agentic 访问——最多 30 次 LLM 迭代、400,000 累计输入输出 token 上限、900 秒墙钟时间上限、top-10 retriever；LLM-Wiki——离线编译、exact title matching 跨链；GraphRAG——离线诱导实体图与社区报告；所有访问条件索引构建一次完成，无开发时超参搜索。
