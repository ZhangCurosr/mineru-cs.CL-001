# 论文速读：DSAgentBench: Can Agents Automate End-to-End Data-Science Workflows in Real Computer Environments?

## 一句话总结
本文提出了首个在真实操作系统环境中评估智能体能否自动化执行端到端数据科学工作流的基准测试 DSAGENTBENCH，包含 275 个覆盖完整数据科学生命周期的任务，并揭示了当前最强智能体（Claude-4.6-Sonnet）在该基准上仅能达到 56.70% 的任务成功率，暴露出大模型在真实计算环境中协同多工具、长程推理与数据分析能力上的显著差距。

## 研究问题与动机
- **核心问题**：AI 智能体能否在真实计算机环境中自主完成从数据采集、清洗、探索、建模到可视化的端到端数据科学工作流？
- **现有基准的不足**：
  1. 现有数据科学基准（如 DS-1000、DABStep、MLAgentBench、DSEval）仅通过静态代码执行评估片段式能力，不涉及真实操作系统交互、多工具协同与中间状态利用。
  2. 现有 GUI/操作系统基准（如 OSWorld、WebArena、VisualWebArena）聚焦通用计算机操作，而非数据科学特有的分析推理与多阶段工作流。
  3. 现有工作缺乏对“端到端”数据科学生命周期的系统性评估，无法反映真实数据科学实践中跨工具（终端、IDE、笔记本、浏览器、数据库）协调与迭代修正的需求。

## 核心贡献（创新点）
1. **提出 DSAGENTBench**：首个在真实操作系统中评估智能体自动化端到端数据科学工作流能力的基准，覆盖数据采集、探索性分析、特征工程、建模、评估与可视化完整生命周期，共 275 个人类 authored 任务。
2. **扩展 OSWorld 环境**：在 OSWorld 基础上集成数据科学核心工具（VS Code、Jupyter Notebook、Chrome 浏览器、SQLite 数据库）以及外部数据源自动获取能力（Kaggle API、OpenML），支持任务特定的环境初始化与数据集预置。
3. **确定性与语义结合的评估体系**：设计基于执行的确定性评测函数，同时验证数值准确性（容忍度 ε=0.01）、可视化输出正确性（轴标签、图例、数据映射）与模型性能阈值；仅约 10% 的任务会调用 LLM 作为视觉裁判进行质量评判，避免评估循环。
4. **大规模基准评测与分析**：对 15 个闭源与开源智能体进行系统评测与消融实验，揭示当前智能体在 UI 接地、工具编排、多步推理与错误恢复方面的根本性局限，为未来自主数据科学智能体研究提供基线与挑战方向。

## 方法详解
- **环境架构**：基于 OSWorld，运行 Ubuntu 操作系统（分辨率 1920×1080），预装 Python 及常用数据科学库，提供 VS Code、Jupyter Notebook、Chrome 浏览器作为可用工具；支持通过 Kaggle API、OpenML、直接 URL 与 SQLite 数据库获取数据。
- **观测空间**：两种模式——（i）纯截图；（ii）截图 + Accessibility Tree（A11y），后者通过 AT-SPI 提取 UI 结构化元数据（元素角色、可访问名称、边界框、交互状态）以辅助接地。
- **动作空间**：统一使用 PyAutoGUI 风格的原子化动作集合，包括鼠标操作（MOVE_TO、CLICK、DRAG、SCROLL 等）、键盘输入（TYPING、PRESS、HOTKEY 等）与控制动作（WAIT、DONE、FAIL）。
- **任务配置**：每个任务 $T_i$ 由三元组 $(\mathcal{C}_i, \mathcal{T}_i, \mathcal{V}_i)$ 定义，其中 $\mathcal{C}_i$ 为系统初始状态配置（文件系统、数据集、已安装库、应用），$\mathcal{T}_i$ 为自然语言指令，$\mathcal{V}_i$ 为确定性 Python 评估函数。
- **执行流程**：智能体在每个时间步接收观测 $o_t$，选择动作 $a_t$，环境按转移函数 $s_{t+1}=T(s_t,a_t)$ 更新状态；最大交互步数预算为 15 步（消融实验扩展至 50 步），任务超时时间为 1800 秒。
- **评估设计**：评估函数根据任务类型分别验证输出文件存在性、数值结果容差匹配（如 Pearson 相关系数误差 ≤ 0.01）、可视化元数据完整性与语义对齐，以及分类/回归模型性能阈值（如 accuracy 或 F1 ≥ 0.7）；主指标为任务成功率（评分 ≥ 0.95 的比例）。

## 实验与结果
- **数据集**：275 个任务，来源包括 GitHub（37.1%）、Kaggle（29.8%）、OpenML（18.9%）、SQLite（7.6%）与 Web（6.5%）；数据模态以表格为主（95.3%），少量图像（3.6%）与文本（1.1%）。
- **难度分布**：Hard 47.6%，Medium 46.9%，Easy 5.5%；单阶段任务 43.3%，多阶段任务 56.7%。
- **评估基线**：15 个智能体，涵盖 GPT-4o、GPT-5-mini、GPT-5、O4-mini、Claude-4/4.5/4.6-Sonnet、Gemini-2.5-Pro、OpenAI CUA 等闭源模型，以及 UI-TARS-2B/7B、GUI-OWL-7B、OpenCUA-72B、Jedi-3B/7B 等开源模型。
- **主要结果**：
  - 最强模型 **Claude-4.6-Sonnet**（Screenshot + A11y Tree）总体成功率 **56.70%**，显著领先其他模型。
  - 其次为 **GPT-5**（29.81%）、**GPT-4o**（24.54%）、**Gemini-2.5-Pro**（20.81%）。
  - **所有开源模型**在 Screenshot-only 设置下成功率均低于 **1%**，且均不支持 A11y Tree 输入。
  - 人类参考表现（3 名参与者）达到 **85.09%** 成功率。
  - 各任务类别表现差异显著：EDA（43.3% 的任务）相对较好，而数据获取（DA）、建模（Modeling）与评估（Eval）类任务成功率普遍低于 20%。
  - 增加 A11y Tree 可提升部分模型性能（如 GPT-5 从 23.63% 提升至 29.81%），但收益因模型而异。
- **消融与错误分析**：
  - 将步数预算从 15 增至 50，成功率仅微增（24.54% → 25.81%），表明瓶颈不在步数限制而在接地、规划与推理能力。
  - 开源智能体失败主因是 UI 接地错误（97–98%），而闭源强模型则呈现接地、终端、代码与逻辑错误的混合分布。
  - Jupyter Notebook 环境下的任务成功率显著高于 VS Code，归因于更少的终端与环境故障。

## 相关工作脉络
1. **数据科学代码生成基准**（DS-1000、DABStep、MLAgentBench、DSEval、DSBench）：仅评估孤立代码片段的执行正确性，不涉及真实操作系统交互与多工具协同；本文在此基础上引入完整工作流与真实环境交互。
2. **可视化与图表理解基准**（ChartQA、Text2Vis、VisEval）：聚焦图表生成与视觉问答，未覆盖数据获取、清洗、建模与分析推理；本文将其纳入端到端流程的统一评估框架。
3. **数据科学流水线基准**（DA-CODE、KRAMABench、ARCADE）：部分支持多文件分析与规划，但仍在沙盒化 Notebook 环境中运行，缺乏 OS 级工具协调；本文实现跨应用（终端、IDE、浏览器、数据库）的真实交互。
4. **通用 GUI/操作系统智能体基准**（OSWorld、WebArena、VisualWebArena、AndroidWorld、OfficeBench）：评估智能体的通用计算机操作能力，但未针对数据科学特有的分析推理与迭代修正设计任务；本文填补这一领域空白。
5. **桌面接地与 GUI 智能体**（CogAgent、ShowUI、Ferret-UI、OS-ATLAS、GUI-R1）：改进 grounding 精度与视觉语言动作模型；本文通过提供结构化的 A11y Tree 观测，系统性地研究其对数据科学工作流中接地与交互稳定性的增益。

## 局限性与未来方向
- **开源模型能力受限**：当前评估中所有开源模型均不支持 A11y Tree 输入，仅能在 Screenshot-only 条件下测试，限制了对其真实能力的全面评估。
- **错误分析的样本规模**：详细错误分析仅覆盖 604 条闭源模型轨迹与 150 条开源模型轨迹，可能遗漏罕见失败模式。
- **可视化评估的主观性**：尽管采用确定性检查为主，但约 10% 任务依赖 LLM 视觉裁判进行质量评判，仍存在一定主观偏差与模型偏向风险。
- **环境扩展性**：当前仅基于 Ubuntu/Linux 环境验证，虽设计兼容 Windows 与 macOS，但未在这些平台上进行系统评测。
- **未来方向**：开发更强的 UI 接地与错误恢复机制、支持更多数据科学工具（如 R/RStudio、PyCharm）、引入主动调试与用户交互能力、构建更长 horizon 的多轮迭代分析工作流。

## 研究启发与可借鉴点
1. **“端到端”工作流评估范式**：将数据科学任务分解为覆盖完整生命周期的多阶段流程，而非孤立代码生成，可为其他领域（如生物信息、金融分析）的 Agent 基准设计提供方法论参考。
2. **确定性评估与语义裁判结合**：以规则/数值容差为主、LLM 视觉裁判为辅的混合评估策略，既能保证稳定性又能捕捉输出质量，值得在其他生成式任务基准中推广。
3. **A11y Tree 辅助 UI 接地**：在 GUI 智能体观测中引入结构化 UI 元数据，可显著提升复杂界面操作成功率；这对研究高复杂度桌面应用自动化具有直接借鉴价值。
4. **任务难度与步骤预算的解耦分析**：通过消融实验证明增加步数预算并不能根本改善性能，提示未来工作应聚焦于规划与推理能力提升，而非单纯延长交互 horizon。
5. **人类性能作为参考基线**：引入人类专家在同一环境下的表现（85.09% 成功率）作为 upper-bound 参照，有助于更清晰地量化当前 AI 能力的真实差距。

## 关键术语表
- **DSAGENTBENCH**：首个在真实操作系统环境中评估智能体自动化端到端数据科学工作流能力的基准测试，包含 275 个任务与确定性评估函数。
- **OSWorld**：用于在真实计算机环境中评估多模态智能体开放域任务的基准框架，本文在其基础上扩展数据科学工具链。
- **Accessibility Tree (A11y)**：通过 AT-SPI 提取的 UI 结构化元数据（元素角色、名称、边界框等），与截图结合可提升智能体的界面接地精度。
- **Deterministic Evaluator**：基于规则与数值容差的自动化评估脚本，验证输出文件的正确性、可视化元数据完整性与模型性能阈值。
- **End-to-End Data-Science Workflow**：从数据采集、清洗、探索性分析、特征工程、建模到可视化报告生成的完整数据科学流程。
- **Tool Orchestration**：智能体在多个应用程序（终端、IDE、浏览器、数据库）之间协调切换、传递状态与执行跨应用操作的能力。

## 可复现要素
- **数据集**：275 个任务已开源，所有数据集（来自 Kaggle、OpenML、GitHub、SQLite）均已预下载并与基准一起发布；代码仓库：https://github.com/vis-nlp/DSAgentBench。
- **代码/权重**：基准环境配置、评估函数、模型推理脚本均已开源；闭源模型通过 API 调用，开源模型使用 vLLM 在 GCP 上部署。
- **关键超参**：屏幕分辨率 1920×1080，温度 temperature=0.1，top-p=0.9，最大输出 token 2000，任务超时 1800 秒，最大交互步数 15（消融扩展至 50），动作后延迟 2.0 秒。
- **硬件环境**：闭源模型在 VMware Ubuntu VM 上运行；开源模型在 GCP n1-standard-4 实例（Docker + vLLM）上并发推理。
